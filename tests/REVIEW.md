# スマホ利用の点検結果（2026-09-07）

ローカルの修正後コードに対して、Chromiumのモバイル・タッチエミュレーション42項目とService Workerの単体テスト3項目が通過。公開先への反映は実施していない。

## 修正内容

|問題|対応|
|ペア右側の名前の80〜90%位置をタップすると、近くの✕が反応してペアが解除される|タッチ端末では✕を隠し、選択バーに「ペア解除」を追加|
|6名定員に8名を配置して保存すると、再読み込みで末尾2名とそのペアが外れる|手動配置と同様に定員超過を保持|
|選択したゲストを無効にしても割当が可能|無効化時の選択解除と割当時の有効性チェック|
|ゲスト名の編集がコートに即時反映されず、入力確定時の再描画でタップを失う|入力中に配置表示・保存を更新し、確定時の再描画を廃止|
|ゲスト名にHTML記号を含むとタグとして解釈される|文字として表示|
|ドラッグ後のclickを通常のタップとして処理する経路がある|既存のドラッグ直後フラグを各タップ経路でも確認|
|撮影ライブラリ未読込・撮影失敗・連打で一時的な画面拡張が残る|事前確認、同時実行防止、finallyで復元|
|ブラウザ保存を使えないと起動処理が停止する|バックアップ日時の読込失敗を処理し、保存失敗を画面通知|
|保存失敗時のバックアップが古い内容または空になる|操作中の最新データから直接書き出す|
|不正なバックアップを既存データに上書きする|構造検証を先に行い、保存途中のエラーでは旧データへの復旧を試みる|
|PWA更新で同一サイトの別アプリのキャッシュまで削除する|このアプリのキャッシュ名のみ削除|
|サーバーのHTTPエラーページをアプリとして保存する|HTTP失敗時は既存のキャッシュを利用|

保存復元ではゲスト枠不足、欠席者の配置、重複ペアも補正する。画面回転時には選択バーの高さに合わせて下余白を再計算する。

## 検証範囲

- 幅320・360・390・430pxおよび844pxの横向きでページの横はみ出しを確認。
- 実際のtouchscreen.tapによる名簿選択、配置、プールへ戻す、欠席・復帰、ペア作成・移動・解除。
- Undo、プリセット3種類、コート入替、大会ペア適用・解除。（2026-10-14 以降はレイアウト12種類に置き換え。下記「追加点検」参照）
- 定員超過配置の再読込、ゲスト編集、バックアップ復元、保存失敗時のバックアップ。
- 撮影ライブラリ未読込・撮影失敗・二重実行を模擬。
- Service Workerのキャッシュ削除範囲、HTTPエラー、オフライン時の分岐を単体テスト。

`mobile-results.json` に個別結果、`mobile-review.png` に修正後画面を保存。

## 追加点検（2026-10-14：面配置の固定・レイアウト12種類・選択色）

- 既定の4コートが 上段C D ／ 下段A B に並ぶこと。
- 全12レイアウト（4コート／2面+2面 横・縦／2面+1面+1面 上下左右／1面+3面 単独C・D・A・B／4面統合）の画面配置、重なりなし、幅320pxで横はみ出しなし、定員＝6人×面数。
- 種類ボタン→位置ボタンの実タップ切替、前回選んだ位置の記憶と再読込後の復元。
- レイアウト変更時のメンバー引き継ぎ（同じ面のコートへ）とUndo。
- 上下入替：面の位置は固定のままメンバーが上下で入れ替わる、統合の形も上下反転、自分で付けたコート名はメンバーと一緒に移る、縦統合では何もしない。
- 旧形式（面情報なし）の保存データの移行：4コートは名前の面へ、2面のコートは旧画面の位置どおりに C+D ／ A+B へ。
- 選択のオン/オフ：実タップで選択すると塗りつぶし、解除すると元の色に完全に戻る（旧版は解除後もホバー色が残っていたことを確認済み）。ペアのメンバーも選択色が出る。
- 4面統合で12組のペアの色がすべて異なる。
- 撮影画像の撮影日見出しとファイル名が端末の日付になる（日本時間の朝7:30＝UTCでは前日、に固定して確認）。見出しは撮影用の複製にだけ入り、実際の画面は変わらない。本物のhtml2canvas（CDN）でもPC・スマホ幅で画像を目視確認。

## 未検証

iPhone実機のSafari、Android実機、ソフトウェアキーボード、OSの画像共有・ファイル保存、実際のCDNを使った画像生成、ホーム画面追加・PWA更新の一連の実機動作は未検証。ドラッグの端末別ジェスチャー挙動も実機確認が必要。全環境で不具合がないことを保証する検査ではない。

## 再実行

```text
python tests/mobile_check.py
node tests/service_worker_check.js
```

Python Playwrightと対応するChromiumが必要。テスト用のローカルHTTPサーバーと隔離されたブラウザを使用し、普段使っているブラウザのデータには触れない。
